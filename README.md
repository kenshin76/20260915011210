# 모바일 상품권 판매 사이트 보안 강화·개편 — 제안 자료 (위시켓 158459)

웹 제안서와 프로토타입 두 가지를 한 저장소에 담았습니다. 빌드 과정이 없는 정적 파일이며, GitHub Pages 가 저장소 루트를 그대로 웹 루트로 씁니다.

| --- | --- |
| 첫 화면 (두 자료 안내) | `https://kenshin76.github.io/20260915011210/` |

## 구성

```
/
├── index.html              첫 화면 — 두 자료로 분기
├── 404.html                잘못된 주소일 때 자료 목록 안내
├── robots.txt              전체 크롤링 차단
├── .nojekyll               GitHub Pages 의 Jekyll 처리 건너뛰기
├── .github/workflows/
│   └── pages.yml           push 시 자동 배포
├── proposal/               웹 제안서 (10개 섹션)
│   ├── index.html
│   └── assets/{style.css, app.js}
└── prototype/              상품권 스토어 프로토타입 (20화면)
    ├── index.html
    └── assets/{style.css, data.js, app.js, img/}
```

두 자료 모두 자산을 상대 경로(`assets/...`)로 참조하므로, 저장소 이름이나 하위 경로가 바뀌어도 그대로 동작합니다.

## 배포

`main` 브랜치에 push 하면 `.github/workflows/pages.yml` 이 저장소 전체를 그대로 올립니다. 워크플로가 `actions/configure-pages@v5` 를 `enablement: true` 로 호출하므로 **저장소 설정에서 Pages 를 따로 켜지 않아도** 첫 실행 때 켜집니다.

```bash
git push -u origin main
```

첫 push 뒤 Actions 탭에서 `Deploy to GitHub Pages` 가 초록색이 되면 위 주소가 열립니다. 보통 1~2분 걸립니다.

> **예전 화면이 보이면 브라우저 캐시입니다.** GitHub Pages 는 HTML 을 약 10분간 캐시합니다. 강제 새로 고침(⌘⇧R / Ctrl+F5) 하십시오.

## 공개 범위 — 반드시 확인해 주십시오

**GitHub Pages 는 저장소가 Private 이어도 무료 플랜에서 페이지가 공개됩니다.** 모든 페이지에 `noindex` 를 넣고 `robots.txt` 로 크롤링을 막아 검색에는 노출되지 않지만, **주소를 아는 사람은 누구나 열 수 있습니다.** 발주사 담당자에게만 주소를 전달해 주십시오.

저장소에 올리지 않는 것 — `.gitignore` 로 제외했습니다.

| 제외 대상 | 이유 |
| --- | --- |
| 루트의 `제안서.md`, `요구사항.md` | 제출 원문과 공고 원문. 웹 제안서로 요약해 공개합니다 |
| `verify_*.py`, `t_*.js` | 검증 스크립트. 단가·금액이 상수로 들어 있습니다 |
| `*.pptx`, `*.pdf`, `*.docx`, `design/` | 대외비 자료 |
| `prototype/assets/img/*.png` | 화면이 쓰지 않는 PNG 원본 약 25 MB. 원본은 Mac 작업 폴더에 남아 있습니다 |

## 프로토타입 확인용 계정

프로토타입은 서버 없이 브라우저 안에서만 도는 **화면 확인용 자료**입니다. 아래 값은 실제 시스템의 계정이 아니라 화면 흐름을 확인하기 위한 예시이며, 소스(`prototype/assets/app.js`)를 열면 그대로 보입니다. 실제 구축 시에는 이런 값이 클라이언트 코드에 들어가지 않습니다.

| 구분 | 값 |
| --- | --- |
| 사용자 로그인 | 아이디 `01028410007` · 비밀번호 `Gift!2026` |
| 관리자 로그인 | 아이디 `admin01` · 비밀번호 `Admin!2026` |
| 관리자 2차 인증번호 | `204815` |

## 5분 안에 보실 것

1. **웹 제안서 §4 기간·예산 의견** — 표준 산정 95~135 MD 와 공고 예산으로 확보되는 40 MD 의 차이, 그 안에서 무엇을 줄였는지.
2. **프로토타입 → 상품권 번호 확인 흐름** — 마스킹 상태에서 시작해 1회용 확인 코드 → 3분짜리 열람권 → 자동 재잠금까지 직접 눌러 보실 수 있습니다.
3. **프로토타입 → 주문·결제 화면의 금액 조작 시연** — 브라우저가 보낸 금액을 서버가 쓰지 않는다는 것을 눈으로 확인하실 수 있습니다.
4. **프로토타입 → 관리자** — 상품별 결제 수단 판매가·노출 설정, 재고 암호화 등록, 회원 유선 승인, 입금 확인(앱 알림 / 가상계좌), SSL·알림톡·개인정보 설정.
