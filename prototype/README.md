# 상품권 스토어 — 프로토타입 (위시켓 158459)

공고의 요구사항을 화면으로 옮긴 **동작하는 프로토타입**입니다. 사용자 12개 + 관리자 8개, 모두 **20개 화면**이며 빌드 과정 없이 정적 파일로만 구성되어 있습니다.

```
prototype/
├── index.html            기본 HTML (해시 라우팅 SPA)
├── assets/
│   ├── style.css         토큰 → 기본 → 헤더/푸터 → 홈 → 커머스 → 폼
│   │                     → 번호 확인 → 관리자 → 공통 UI → 반응형
│   ├── data.js           목(mock) 데이터 — 상품·주문·회원·재고·설정·알림톡
│   ├── app.js            라우터와 화면. 라이브러리 의존성 없음
│   └── img/              사진형 WebP(히어로·상품 5종·에디토리얼 3종)와 SVG UI 이미지
├── .nojekyll             GitHub Pages에서 Jekyll 처리 건너뛰기
└── README.md             이 파일
```

## 주요 이용 흐름

1. **홈 → 상품권 보러 가기** — 인기 상품과 전체 상품을 확인하고 원하는 권종을 선택합니다.
2. **상품 상세 → 주문하기** — 결제 수단별 판매가와 회원 등급에 따른 이용 가능 여부를 확인합니다.
3. **주문 내역 → 주문 상세** — 결제가 완료된 주문에서 본인 확인 후 상품권 번호를 확인합니다.
4. **관리자 화면** — 주소 뒤에 `#/admin`을 붙여 접속합니다. 기능 확인용 비밀번호는 `Admin!2026`, 2차 인증번호는 `204815`입니다.
   상품·재고·회원·주문·입금·알림톡·팝업을 운영 화면에서 관리할 수 있습니다.

## 프로토타입의 경계

- **실제 결제·발송은 일어나지 않습니다.** 브랜드명·회원명·상품권 번호·계좌번호는 모두 가상입니다.
- 화면 전환은 해시 라우팅이며, 상태는 새로고침하면 초기값으로 돌아갑니다.
- 실제 구축에서는 **쇼핑몰과 관리자를 서버·도메인 단위로 분리**합니다. 이 프로토타입은 한 파일 안에서 그 화면 구성만 보여 드립니다.
- 보안 문구는 화면에 적힌 범위까지만 설명합니다. 무엇을 막고 무엇을 막지 못하는지는 제안서 §7.3에 함께 적었습니다.

## 배포

저장소 루트가 웹 루트이므로 이 폴더는 하위 경로로 서비스됩니다.

```
https://<user>.github.io/<repo>/prototype/
```

모든 자산이 상대 경로(`assets/...`)라서 저장소 이름이나 하위 경로가 바뀌어도 그대로 동작합니다. 배포 후 예전 화면이 보이면 브라우저 캐시입니다 — 강제 새로고침(⌘⇧R / Ctrl+F5) 하십시오.

> **공개 범위 주의.** GitHub Pages는 저장소가 Private이어도 무료 플랜에서 페이지가 공개됩니다. 검색 노출은 `noindex`로 막아 두었지만, 주소를 아는 사람은 열람할 수 있습니다.

## 외부 의존성

자바스크립트 라이브러리는 쓰지 않습니다. 웹폰트 2종만 CDN에서 불러옵니다.

- Pretendard — `cdn.jsdelivr.net`
- Noto Serif KR — `fonts.googleapis.com`

폰트가 차단된 환경에서도 시스템 대체 서체로 정상 동작합니다. 실제 구축 시 공급망 의존을 없애야 하면 두 서체를 자체 호스팅합니다.

메인·상품·에디토리얼 이미지에는 브랜드명·상품권 번호·바코드가 없는 AI 생성 목업을 사용했으며, 표시용 WebP를 함께 두어 이미지 전송량을 줄였습니다.
